LAYER 1: Autonomous Planners
1A. Cycle Planner
Purpose: Autonomous daily planning — looks at company state and proposes what should happen next without user input.

Reads: company context, recent completions, active work, roadmap documents
Outputs: task proposals injected into the queue
You can view/reject these like any other task
What's opaque to me: The exact planning algorithm, priority weighting, how it decides between competing priorities. I know it exists as a platform MCP mount (cycle_planning) but I don't have direct access to its internals.

1B. Boost Planner
Purpose: Proposes tasks proactively — appears to be the system that generates "suggested" tasks based on company state.

What I know:

Respects disabled agents (won't propose tasks for agents you've turned off)
Can be overridden by user preferences
Runs independently of my chat sessions
What's opaque: Trigger conditions, frequency, planning model.

1C. Recurring Task Scheduler
Purpose: Cron-like system that creates task instances from templates on a schedule.

Inputs: Recurring task definitions (title, description, frequency, tag, priority)

Frequencies: daily, weekdays (Mon-Fri), weekly (specific days), monthly (specific day 1-28)

Output: Creates a new task instance in the queue each time it fires. Each run consumes 1 credit.

Failure handling: If credits = 0, the instance still creates but can't execute.

LAYER 2: Task Queue + Dispatch
Queue Structure
Every task has:

{
  id: number
  title: string
  description: string        // The "brief" the agent reads
  tag: string                // Routes to which agent type
  task_type: string          // bug, feature, refactor, css, research, etc.
  status: todo | in_progress | completed | failed | rejected
  priority: low | medium | high | critical
  complexity: 1-10
  estimated_hours: 0.5-4
  position: number           // Queue order (lower = runs first)
  suggested_agent_id: number // Optional: specific agent
  related_task_ids: number[] // Links to prior tasks (required for bugs)
  metadata: object           // Optional structured data
  executability_type: can_run_now | needs_new_connection | manual_task
}
